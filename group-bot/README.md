# ESnow — уведомления в рабочую группу

## Диагностика — версия 2026.11.14-monitoring

Команды в личном чате привязанного владельца:

- `/last` — последние 10 обнаруженных обновлений: версия, время обнаружения и
  отправки по Москве, состояние очереди, последняя ошибка и получатель отправки.
  У старых записей время неизвестно; оно не подменяется временем обновления бота.
- `/test` — отправляет явно помеченное тестовое сообщение в настроенный чат
  уведомлений (группа или личный чат). Для группы результат дополнительно приходит
  владельцу лично. Тест не попадает в историю игровых обновлений и не меняет версии.
  Повторите команду новым сообщением, если хотите выполнить ещё один тест.
- `/status` и `/sources` продолжают работать.

Автоматические предупреждения приходят только владельцу:

- Источник: после трёх неудачных проверок подряд. Успех сбрасывает счётчик.
- Доставка игрового уведомления: после первой ошибки. Сообщение остаётся в очереди.
- После ранее отправленного предупреждения — одно сообщение о восстановлении.
  Для доставки восстановление подтверждается успешной отправкой игрового уведомления.

Счётчики и состояние предупреждений переживают перезапуск. Если личное сообщение
отправить нельзя, бот повторяет попытку позже. При полном отсутствии интернета или
остановке процесса он не может оповестить через Telegram в этот момент. Если сбой
источника закончился до отправки предупреждения, устаревшее предупреждение отменяется.
Потеря ответа Telegram после принятия сообщения всё ещё может привести к повтору.
Автоматические предупреждения — о работе мониторинга, не о сбоях игровых серверов.

Обновление: STOP-AUTOSTART.cmd, резервная копия папки, замена файлов программы
с сохранением settings.json и state.sqlite3, затем AUTOSTART.cmd. SETUP.cmd не нужен.
Новые поля истории добавляются автоматически. После запуска проверьте /status,
/test и /last. Тестовую отправку в реальный Telegram нужно выполнить на вашем ПК.

Проверка каждые 5 минут. Как только обнаружено изменение версии, бот отправляет
отдельное сообщение, состоящее только из названия игры. Пока рабочая группа не
привязана, сообщение приходит в личный чат владельцу. После привязки — в группу.
В первый запуск сохраняются исходные версии: старые обновления не рассылаются.
Кнопок, подписок и отчётов в 08:30/20:30 в этой версии нет.

В личном чате владельца доступны /status и /start: время запуска и последней
завершённой проверки (МСК), число ответивших источников и ошибок, прогресс текущего
обхода, получатель уведомлений, очередь и ошибка отправки. После перезапуска
статистика проверок собирается заново. Ответ подтверждает, что процесс работает,
но ошибки источников нужно оценивать отдельно. В группе команды статуса не отвечают.
Опрос команд выполняется отдельно от запросов к игровым источникам.

## Установка

1. Остановите тестового бота через его STOP-AUTOSTART.cmd и закройте RUN.cmd.
2. Распакуйте новую версию в отдельную постоянную папку, например C:\ESnowGroupBot.
3. Запустите SETUP.cmd и локально введите токен. Можно использовать прежнего бота.
4. Откройте показанную установщиком ссылку на личный чат бота и нажмите «Запустить»
   или отправьте туда показанную команду /start с одноразовым кодом.
5. Установщик подтвердит личный чат в окне компьютера. Запустите AUTOSTART.cmd.
   Теперь новые обновления будут приходить вам лично.
6. Разрешите запуск от администратора Windows. Отправьте /status в личный чат бота.
   Должен прийти ответ «ESnow работает», версия 2026.11.14-monitoring. Первый обход
   может ещё выполняться — повторите /status через несколько минут.

Пока открыт SETUP.cmd, команда /start с новым кодом используется только для
привязки. После сообщения Connected to настройка завершена, но сам мониторинг
нужно запустить через AUTOSTART.cmd. Не используйте код от прошлого запуска.
Вместо автозапуска можно открыть RUN.cmd и оставить окно открытым; не запускайте
RUN.cmd и AUTOSTART.cmd одновременно. При отсутствии ответа проверьте bot.log
и состояние задачи ESnowGameUpdates в Планировщике заданий Windows.

### Подключение рабочей группы позже

1. Остановите бота через STOP-AUTOSTART.cmd; если открыт RUN.cmd, закройте его.
2. Добавьте бота в группу, разрешите отправку сообщений и запустите CONNECT-GROUP.cmd.
3. Отправьте показанную команду /connect@имя_бота с одноразовым кодом в группу.
   Отправитель должен быть владельцем привязанного личного чата и администратором группы.
4. После подтверждения запустите AUTOSTART.cmd. Новые уведомления пойдут в группу.

При обновлении этой версии сохраните settings.json и state.sqlite3. Если раньше
была привязана только группа, она продолжит работать; SETUP.cmd добавит личный чат,
сохранив группу при использовании того же токена. Повторно уже отправленные
уведомления при смене чата не рассылаются. При ошибке отправки в привязанную группу
уведомление остаётся в очереди, а не перенаправляется в личный чат.

Не переносите settings.json или state.sqlite3 от тестовой версии: назначение и
структура данных изменились. Сам токен можно использовать повторно.
Тестовый и новый бот не должны работать одновременно с одним токеном.
Задача Windows использует прежнее имя ESnowGameUpdates и при установке обновляется.
Все участники рабочей группы видят уведомления без личного /start.

## Источники и границы проверки

Версия 2026.11.14-accuracy: исправлены пропуски сборок Fortnite внутри одного
номера релиза, подстановка выдуманной версии LoL при сбое Data Dragon, фильтрация
анонсов и ПТС в новостях, повторный выпуск сборки после отката. Warface теперь
использует новости русского издателя вместо международной версии Steam.

Команда /sources в личном чате владельца показывает ограничения источников и
последние ошибки. /status отдельно показывает количество косвенных источников.
Сейчас 104 записи используют идентификаторы сборок/манифестов, 18 — косвенные
сигналы. Это НЕ означает гарантию полного покрытия 104 клиентов: SteamCMD API
и Fortnite-API — сторонние зеркала; сборка Steam может измениться для другой ОС.
Для Call of Duty HQ нельзя подтвердить, что изменился именно Warzone.

Подробный аудит и оставшиеся ограничения: SOURCE-AUDIT.md.
CHECK-SOURCES.cmd выполняет независимый обход и сохраняет source-check.json.
Он не читает токен, не меняет базу и не отправляет уведомления; отчёт можно
передать для диагностики сетевых проблем на конкретном ПК.

### Обновление с версии status

Остановите бота, сохраните резервную копию папки, замените файлы программы.
Сохраните свои settings.json и state.sqlite3. Запустите AUTOSTART.cmd; SETUP.cmd
повторять не нужно. Схема очереди обновляется автоматически в транзакции,
сохранённые и ожидающие отправки записи сохраняются. При изменении формата
источника (Fortnite, Warface, Crossout, Deadlock) первое успешное наблюдение
создаёт новую базовую версию без ложного сообщения об обновлении. Изменение игры
в этот переходный период нельзя отделить от изменения источника.

sources.py содержит адаптеры тестовой версии. Это ещё не гарантия полного покрытия
клиентских обновлений: часть адаптеров использует патч-ноты, Lesta Wiki или игровые
ресурсы Riot, которые могут появляться с задержкой. Для ряда игр из других магазинов
используется сигнал Steam, который может не совпасть с обновлением другого лаунчера.
Эти источники требуют дальнейшей проверки для строгого производственного мониторинга.
Одинаковые названия игр представлены один раз — используется первая запись списка.

Ошибки источников записываются в bot.log, в рабочую группу технические сообщения не
отправляются. TLS проверяется с системными сертификатами и комплектом cacert.pem
из https://curl.se/ca/cacert.pem (Mozilla CA bundle, получен 13.11.2026).
Это дополнение доверенных корней, не отключение проверки сертификатов.

Очередь переживает перезапуск. Если Telegram принял сообщение, но ответ потерялся,
при повторной отправке возможен дубль. Изменения между двумя обходами могут быть
пропущены, если источник не хранит историю. Интернет и включённый ПК обязательны.

## Код

- bot.py — привязка личного чата и группы, цикл проверок, SQLite и отправка уведомлений.
- sources.py — получение версий и сигналов обновления.
- games.json — список игр и источников.
- test_group.py — проверка исходной версии, очереди, перезапуска и формата сообщения.

Проверка: python -m unittest discover -v
